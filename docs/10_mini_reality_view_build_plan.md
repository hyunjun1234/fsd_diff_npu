# 축소판 생성형 리얼리티 뷰 구현 계획

이 문서는 테슬라 v15 리얼리티 뷰 렌더러의 구조를 작게 줄여, 라즈베리파이 5와 지금 달려 있는 Hailo-8, DX-M1에서 돌리는 생성형 렌더러를 만드는 단계별 계획입니다.

왜 이 크기와 구조를 골랐는지는 [09 문서](09_tesla_3b_1b_models.md)에 있습니다. 이 계획은 [구현 계획](03_pi5_hailo8_dxm1_implementation_plan.md) 4.8절의 "생성형 렌더러 가능성 시험"을 구체화한 것이고, 기존 0~5단계와 구분하려고 단계 이름을 G1~G6으로 붙였습니다.

## 1. 목표와 범위

목표는 카메라 5대의 영상에서 자차 뒤쪽 위 가상 카메라(chase 시점)의 화면을 생성 모델이 바로 만드는 것입니다. 지금의 v15풍 화면([v15풍 화면 문서](v15_render.md))은 검출 결과에 3D 모델을 세워 그리지만, 생성형 렌더러는 검출되지 않은 물체나 도로 모양도 영상으로 그릴 수 있습니다.

첫 목표치는 다음과 같이 잡습니다. 출력 해상도 128x256(화면에서는 키워서 표시), 생성 초당 5프레임 이상, 센서에서 화면까지 300ms 이하, 생성 단계 1~2입니다. 테슬라의 화면 해상도와 36fps에는 한참 못 미치지만, 같은 구조가 엣지 장치에서 도는지 확인하는 것이 이 계획의 목적입니다.

범위 밖인 것은 차량 제어와 3B 규모의 주행 모델입니다. 경로 띠와 회전 화살표를 위한 작은 경로 예측 모델만 선택 단계(G6)로 둡니다.

## 2. 전체 구조

```
카메라 5대 (128x256~192x384로 축소)
   |
   v
공유 인코더 (카메라마다 작은 CNN 백본, NPU)          <- 테슬라 UVE 자리
   |                         |
   v                         v
기존 인식(검출, 세그)       BEVPool (파이 CPU, 구현 완료)
                             |
                             v
                   조건 특징: BEV 특징 + 가상 카메라 자세 + 이전 출력 잠재
                             |
                             v
                   생성기 (합성곱 U-Net 30M 안팎, 1~2단계, NPU)   <- 1B 렌더러 자리
                             |
                             v
                   작은 디코더 (잠재 16x32 -> 영상 128x256, NPU)  <- tiny decoder 자리
                             |
                             v
                           화면
```

테슬라처럼 인코더 특징을 인식과 렌더러가 함께 씁니다. 생성기는 이전에 만든 화면의 잠재를 입력으로 받아 다음 화면을 만들므로, 매번 처음부터 그리지 않고 고쳐 그리는 방식이 됩니다. 어텐션은 가장 작은 해상도에서만 쓰거나 아예 빼서 NPU 연산자 문제를 피합니다([엣지 NPU 구성과 모델 선정](edge_npu_model_selection.md)).

NPU 배치의 출발점은 Hailo-8에 기존 검출을 두고, DX-M1에 공유 인코더와 생성기와 디코더를 두는 것입니다. DX-M1은 보드 메모리(4GB)가 있어 여러 모델을 올려 두기 좋습니다. 지금 DX-M1이 맡은 도로 세그와 깊이는 주기를 늘리거나 공유 인코더의 헤드로 합칩니다. 실제로 어느 쪽이 빠른지는 G5에서 재고 정합니다.

## 3. 학습 정답을 만드는 방법

차 위 가상 카메라에서 찍은 실제 영상은 없으므로 정답 영상을 따로 만들어야 합니다. 이 계획의 성패가 여기에 달려 있습니다. 두 방법을 차례로 씁니다.

첫째는 기존 v15풍 렌더러를 정답으로 쓰는 방법입니다. 주행 녹화를 학습 서버에서 다시 돌려 chase 시점 화면을 저장하면 입력 영상과 정답 화면의 쌍이 바로 생깁니다. 준비가 빠르고 파이프라인 전체를 시험하기 좋지만, 생성 모델이 렌더러보다 나아질 수는 없습니다.

둘째는 주행 구간마다 3D로 재구성해 정답을 만드는 방법입니다. 녹화된 카메라 영상으로 구간별 3D Gaussian Splatting을 만들고 chase 시점에서 렌더링합니다. 실제 장면의 질감과 모양이 담기지만, 움직이는 차와 사람은 흐리게 나오고 구간마다 학습 서버에서 오프라인 계산이 필요합니다. 구간 하나에 드는 시간은 확인 필요입니다. 정확한 재구성에는 카메라 자세가 필요하므로 G1 전에 카메라 보정([모형 보정 문서](phase1_model_rig_calibration.md))이 끝나 있어야 합니다.

두 정답을 섞어 쓸 수도 있습니다. 바닥과 건물은 3D 재구성에서, 움직이는 물체는 v15풍 렌더러에서 가져와 합치는 방식입니다. 이것은 G4 결과를 본 뒤 정합니다.

## 4. 단계와 완료 기준

| 단계 | 내용 | 기간 |
|---|---|---|
| G1 | 정답 데이터 만들기 | 1~2주 |
| G2 | 작은 오토인코더 | 1주 |
| G3 | 공유 인코더와 조건 특징 | 1~2주 |
| G4 | 생성기 학습 | 2~4주 |
| G5 | NPU 변환과 파이 통합 | 2~3주 |
| G6 | 경로 예측 (선택) | 2주 |

기간은 이 문서의 추정입니다. 단계별 내용과 완료 기준은 아래와 같습니다.

### 4.1 G1: 정답 데이터 만들기

주행 녹화([주행 녹화 문서](drive_recording.md))에서 카메라 5대 프레임을 시각으로 묶고, 3장의 첫째 방법으로 chase 시점 정답 화면을 만듭니다. 시점은 처음에는 chase 하나로 고정하고, 나중에 높이와 각도를 조금씩 바꾼 시점을 섞어 "임의 시점"으로 넓힙니다. 시험 세트는 학습에 쓰지 않는 주행 구간으로 따로 잠급니다. 학습 파이프라인의 고정 시험 세트 방식([학습 파이프라인 문서](training_pipeline.md))을 그대로 따릅니다.

완료 기준은 입력과 정답 쌍 10만 개 이상(카메라 30fps를 5fps로 솎으면 약 5.5시간 분량), 시험 구간 분리, 3D 재구성 정답 시험 구간 하나입니다.

### 4.2 G2: 작은 오토인코더

128x256 영상을 16x32x4 잠재로 줄였다가 되살리는 오토인코더를 학습합니다. Stable Diffusion용으로 나온 작은 오토인코더(TAESD)의 구조를 참고하고 주행 영상으로 학습합니다. 디코더는 파라미터 수백만 개 이하로 작게 만듭니다. 테슬라가 SRAM에 올렸다는 작은 디코더에 해당합니다.

이 단계에서 디코더를 먼저 DX-M1과 Hailo-8로 변환해 봅니다. 합성곱과 업샘플링만 쓰므로 가장 위험이 적은 부분이고, 여기서 막히면 뒤 단계 전체를 다시 생각해야 하기 때문입니다.

완료 기준은 시험 세트 재구성 PSNR 26dB 이상(목표값, 확인 필요), 디코더의 DX-M1 변환 성공, 파이에서 디코더 한 번 20ms 이하입니다.

### 4.3 G3: 공유 인코더와 조건 특징

카메라마다 작은 CNN 백본으로 특징을 뽑고, 이미 만든 BEVPool([04번 측정](measurements/04_bevpool_cpu.md), 카메라 4대에 스레드 4개로 2.73ms)로 BEV 특징을 만듭니다. 백본은 4단계 FlashOcc 계획의 이미지 백본을 그대로 쓰는 것이 가장 좋습니다. 인식과 렌더러가 한 백본을 나눠 쓰는 테슬라 구조와 같아지고, NPU 연산도 한 번으로 끝납니다.

가상 카메라 자세(높이, 거리, 각도)는 작은 벡터로 만들어 생성기에 넣습니다. 학습할 때는 백본을 고정하고 BEV 이후만 학습해서 4070 메모리 안에 맞춥니다.

완료 기준은 학습 서버에서 G1 데이터 전체의 조건 특징 미리 계산, 파이에서 백본과 BEVPool 합계가 한 사이클 100ms 이하입니다.

### 4.4 G4: 생성기 학습

잠재 16x32를 다루는 합성곱 U-Net을 30M 안팎으로 만들고 MeanFlow 방식([09 문서](09_tesla_3b_1b_models.md) 3장)으로 학습합니다. 입력은 노이즈를 섞은 현재 잠재, 이전 프레임의 잠재, BEV 특징, 가상 카메라 자세입니다. 학습 연산은 RTX 4070에서 약 하루로 계산됩니다([09 문서](09_tesla_3b_1b_models.md) 5.2절). 결과가 모자라면 100M까지 키웁니다(약 3일).

같은 U-Net을 생성 모델이 아닌 단순 회귀(L1과 지각 손실)로 학습한 것을 비교 기준으로 반드시 함께 만듭니다. 데이터가 적을 때는 회귀가 더 깨끗한 화면을 낼 수도 있고, 그 경우 생성 모델의 이점은 검출되지 않은 물체를 그럴듯하게 채우는 데에만 남습니다. 두 결과를 보고 G5에 올릴 모델을 고릅니다.

평가는 시험 구간에서 PSNR, LPIPS, 그리고 연속 프레임의 깜빡임(이웃 프레임 차이)을 봅니다. 사람이 영상으로 보고 판단하는 단계도 넣습니다.

완료 기준은 시험 구간에서 회귀 기준보다 LPIPS가 낮거나 같고, 1단계 생성과 4단계 생성의 차이가 작으며, 30초 영상에서 눈에 띄는 깜빡임이 없는 것입니다.

### 4.5 G5: NPU 변환과 파이 통합

생성기를 ONNX로 내보내고 DX-COM으로 .dxnn(INT8)을 만듭니다. 보정 이미지는 G1의 실제 주행 프레임을 씁니다. INT8 변환 후 시험 세트 LPIPS가 크게 나빠지면 어느 층이 문제인지 찾아 그 층만 바꾸거나 CPU로 넘깁니다. Hailo-8 쪽 배치도 같은 방법으로 만들어 비교합니다.

파이에서는 `run_demo.py`에 생성형 화면을 새 시점으로 넣고, 기존 v15풍 화면과 나란히 볼 수 있게 합니다. 생성은 테슬라처럼 낮은 주기로 돌리고, 사이에 낀 프레임은 이전 결과를 자차 움직임만큼 밀어서 채웁니다. 발열은 기존 `--thermal` 단계에 생성기 주기 늘리기를 더합니다.

완료 기준은 파이에서 생성 초당 5프레임 이상, 센서에서 화면까지 300ms 이하, 30분 연속 실행에서 과열 종료 없음, 기존 검출 FPS가 목표(카메라 4대 8 FPS) 아래로 떨어지지 않는 것입니다.

### 4.6 G6: 경로 예측 (선택)

화면에 경로 띠와 회전 화살표를 그리기 위한 작은 모델입니다. 공유 인코더의 BEV 특징과 과거 자차 움직임을 받아 앞으로 3초의 경로를 냅니다. 정답 경로는 녹화 영상에서 구한 자차 움직임(visual odometry)이나 GPS 모듈을 달아 얻습니다. 지금 녹화에는 GPS와 IMU가 없어서 이 단계를 하려면 먼저 하나를 골라야 하며, 어느 쪽이 맞을지는 확인 필요입니다. 결과는 화면 표시에만 쓰고 차량 제어에는 쓰지 않습니다.

완료 기준은 시험 구간에서 3초 뒤 위치 오차 평균 1.5m 이하(목표값)입니다.

## 5. 장비와 비용

학습은 지금의 학습 서버(RTX 4070 12GB, WSL2)로 G1~G5를 모두 할 수 있다고 봅니다. 3D 재구성 정답을 많이 만들거나 생성기를 1B 쪽으로 키울 때만 클라우드 GPU가 필요합니다.

파이 쪽은 지금 장비로 시작합니다. G5에서 DX-M1의 연산자 지원이나 메모리가 걸림돌이 되면 Hailo-10H(AI HAT+ 2, 200달러, 메모리 8GB, [02 문서](02_edge_npu_spec_comparison.md))를 추가 후보로 봅니다. Hailo-10H는 생성형 모델 시연이 있는 유일한 후보이지만 파이 5의 PCIe 하나를 두 NPU가 이미 나눠 쓰고 있어 연결 방법을 따로 정해야 합니다. 두 번째 파이에 다는 방법은 [08 문서](08_pi_offload_options.md)의 렌더링 전용 파이 구성과 합칠 수 있습니다.

## 6. 위험 요소와 대응

정답의 품질이 낮으면 모델도 그만큼만 됩니다. v15풍 렌더러 정답으로 파이프라인을 먼저 끝까지 통과시킨 뒤 3D 재구성 정답으로 바꾸는 순서로 이 위험을 나눕니다.

데이터가 적어 특정 길에만 맞을 수 있습니다. 시험 구간은 학습 구간과 다른 길에서 고르고, 공개 데이터셋 사전 학습은 효과를 본 뒤 정합니다.

NPU 연산자 문제는 합성곱 위주 구조로 피하고, G2에서 디코더를 먼저 변환해 일찍 확인합니다. 그래도 막히는 층은 CPU로 넘기거나 Hailo-10H를 검토합니다.

생성 화면이 실제와 다른 물체를 그릴 수 있습니다. 생성 모델의 본래 성질이므로, 화면에는 기존 검출 결과를 겹쳐 그려 운전자가 실제 인식 결과와 구분할 수 있게 둡니다.

지연은 생성 주기를 낮추고 사이 프레임을 이동 보정으로 채우는 방법으로 줄입니다. 테슬라도 지연이 큰 점을 인정했고 새 특징을 중간에 끼워 넣는 방법으로 줄이겠다고 했습니다([09 문서](09_tesla_3b_1b_models.md) 2.2절). 같은 방법은 G5 이후 과제로 둡니다.
