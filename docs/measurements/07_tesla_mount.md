# 07. 카메라 자리를 테슬라 모델 Y 배치로 바꾼 결과

이 문서는 카메라 장착 위치의 기준값을 테슬라 모델 Y의 같은 역할 카메라 자리로 바꾸고, 같은 녹화 장면으로 BEV 화면 배치가 맞는지 파이에서 확인한 기록입니다. 실제 카메라는 책상 위에 놓여 있어서 거리 값은 의미가 없고, 바닥 영역이 차 앞뒤에 놓이는지만 봤습니다.

## 1. 바꾼 기준값

좌표는 docs/04_tesla_camera_layout.md의 추정치이고(원점 뒷바퀴 축 가운데 바닥, x 전방, y 왼쪽, z 위, m), 각도는 04 문서와 3D 도면(viz/tesla_camera_layout_3d.html)의 추정값입니다. 모두 실측 필요입니다.

| 카메라 | 위치 x, y, z (m) | 방향 (yaw, 아래로 숙인 각) |
|---|---|---|
| 전방 ov5647 (테슬라 전방 광각 자리) | 1.80, -0.06, 1.45 | 0도, 3도 (도면 추정값) |
| 후방 imx708 (테슬라 후방 자리) | -0.95, 0.00, 1.00 | 180도, 20도 (04 문서, 추정) |
| 좌 (four_cam, 앞펜더 리피터) | 2.25, 0.97, 0.92 | 135도, 5도 (도면 추정값) |
| 우 (four_cam, 앞펜더 리피터) | 2.25, -0.97, 0.92 | -135도, 5도 (도면 추정값) |

예전 값은 전방 (1.9, 0, 1.30) 12도, 후방 (-0.9, 0, 1.10) 15도, 좌우 (2.0, ±0.95, 1.05) yaw ±90도 30도였습니다. 좌우 기울기(roll)는 모두 0도로 두었습니다(문서에 없음, 실측 필요).

two_cam_current.yaml의 전방 내부 파라미터도 핀홀 수평 53.5도(Camera Module 1 기본 렌즈 사양)에서 어안 대각 130도 근사(f 423.1px, two_cam_model.yaml과 같은 값)로 바꿨습니다. 130도 광각 렌즈를 핀홀 53.5도로 보면 BEV 범위를 화각과 맞춰 볼 수 없기 때문입니다.

모형 설정(two_cam_model.yaml)은 같은 실차 좌표를 `position_car`로 적고 `scene.scale` 0.1을 곱해 씁니다. 전방은 (0.18, -0.006, 0.145), 후방은 (-0.095, 0, 0.10)이고, BEV는 실차 범위(앞 25m, 뒤 15m, 좌우 12m)와 셀 10cm를 줄인 앞 2.5m, 뒤 1.5m, 좌우 1.2m, 셀 1cm(400 x 240)입니다.

## 2. BEV 범위 계산

scripts/check_mount.py로 계산했습니다(설정만 읽고 IPM 셀 담당 카메라를 구함, 맥과 파이 결과 같음). 원본: 07_mount_two_cam_current.json, 07_mount_two_cam_current_old.json, 07_mount_two_cam_model.json, 07_mount_four_cam.json

| 설정 | 전방 셀 x 범위 (정면 바닥 시작) | 후방 셀 x 범위 (정면 바닥 시작) |
|---|---|---|
| two_cam_current 예전 | 3.98~25 (카메라 앞 2.03m) | -2.43~-15 (카메라 뒤 1.53m) |
| two_cam_current 새 값 | 2.83~25 (카메라 앞 1.62m) | -2.13~-15 (카메라 뒤 1.16m) |
| two_cam_model 새 값 (축척 0.1) | 0.285~2.5 (카메라 앞 0.162m) | -0.215~-1.5 (카메라 뒤 0.116m) |

새 값에서 바닥이 보이는 셀은 전체의 60.0%(예전 41.7%)입니다. 전방 셀은 좌우 12m 끝까지, 후방 셀은 좌우 9.2m까지 덮습니다. 모든 카메라의 셀이 그 카메라가 바라보는 쪽에만 있고(tests/test_tesla_mount.py에서 확인), 차 옆(x -2.1~2.8)은 두 카메라 모두 못 보는 사각지대입니다. 전방 바닥이 x 3.4부터 보이지만 실제 차에서는 보닛이 가려 앞범퍼(x 3.78) 앞부터 쓸 수 있을 것으로 보며 확인 필요입니다.

화소당 바닥 길이(정면 방향, 새 two_cam_current)는 전방 기준 5m에서 4.4cm, 10m에서 17cm, 25m에서 1.0m입니다. 셀 5cm는 5m 안팎에서 영상 해상도와 맞고, 10m 밖은 영상 한 화소가 셀 여러 개로 늘어납니다. 탑뷰 표시용이라 범위와 셀 크기는 바꾸지 않았습니다.

four_cam.yaml은 바닥이 보이는 셀이 95.3%에서 89.1%로 줄었습니다. 펜더 카메라가 뒤쪽 옆을 보므로 차 앞쪽 옆(옆 1.2m 줄에서 x 0.9~3.7m)이 비고, 테슬라는 이 자리를 B필러 카메라로 덮습니다.

## 3. 같은 장면 스냅샷

2026-11-24, 파이5, 녹화 프레임 out/rec/room_100(전방, 후방 각 100장, 방 안 책상)을 `--video`로 넣고 Hailo 백엔드로 30프레임씩 돌렸습니다.

| 파일 | 설정 | 보인 것 |
|---|---|---|
| 07_snapshot_current_old.png | 예전 two_cam_current | 전방 바닥 쐐기가 좁고(핀홀 53.5도) 자차 앞에서 조금 떨어져 시작 |
| 07_snapshot_current_new.png | 새 two_cam_current | 전방 쐐기가 넓어지고 자차 상자 앞 끝에서 시작, 후방 쐐기는 자차 뒤에서 시작 |
| 07_snapshot_model_old.png | 예전 two_cam_model | 모형 크기 탑뷰, 25도 숙인 값 |
| 07_snapshot_model_new.png | 새 two_cam_model | 새 two_cam_current와 같은 모양이 축척 0.1로 줄어 그려짐(거리 고리 0.5m 간격) |

새 설정 두 개 모두 전방 바닥 영역은 자차 상자 앞에, 후방 바닥 영역은 자차 상자 뒤에 놓여 화면 배치는 맞습니다. 두 카메라가 지금 책상에서 같은 쪽을 보고 있어서 쐐기 안의 그림 내용은 의미가 없습니다. 실차 설정과 모형 설정 그림이 같은 모양인 것은 각도와 화각이 같고 위치와 범위만 같은 비율로 줄었기 때문입니다.

다시 찍는 명령(파이 저장소 폴더에서 .venv를 켠 뒤, 결과 out/measure/07_snapshot_*.png):

```bash
timeout -s INT -k 5 90 python3 scripts/run_demo.py --config configs/two_cam_current.yaml --backend hailo --headless --frames 30 --video front=out/rec/room_100/front_%05d.png --video rear=out/rec/room_100/rear_%05d.png --snapshot out/measure/07_snapshot_current_new.png
python3 scripts/check_mount.py --config configs/two_cam_current.yaml --out out/measure/07_mount_two_cam_current.json
```

## 4. 모형 보정 절차에 생긴 변화

전방 카메라가 높이 14.5cm(축척 0.1)에서 거의 수평이라 바닥 체커보드를 놓을 자리가 좁아졌습니다. 합성 영상 시험에서 파이의 OpenCV 4.10은 맥의 4.13보다 코너를 찾는 자리가 적었고, 두 곳 모두에서 되고 검은 칸이 모형 앞범퍼 자리(x 0.378)보다 앞에 오는 자리(전방 0번 코너 원점 앞 50cm, 보드를 돌리면 40cm, 후방 원점 뒤 40cm와 30cm)로 문서와 시험을 맞췄습니다. 전방 카메라가 거의 수평이라 모형 앞쪽 틀이 높으면 바닥을 가리므로, 보닛이 있는 닫힌 차체로 되는지도 확인 필요입니다. 실제 보드에서도 되는지는 확인 필요입니다.
