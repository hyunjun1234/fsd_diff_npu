2단계 끝부분(구현 계획 4.3절 마지막 문단)과 모델 선택지 넓히기입니다. 보정이 없어도 되는 범위만 합니다. 먼저 docs/progress.md, docs/measurements/05_dxnn_sources.md, 06_stage2_dxnn.md 를 읽으세요.

사람이 허락한 것: DEEPX 공식 모델 저장소(sdk.deepx.ai/modelzoo, GitHub DEEPX-AI 조직, DEEPX 공식 문서의 다운로드 주소)에서 .dxnn 을 파이로 받는 것. 다른 출처에서는 받지 마세요. 파이의 DX-RT 3.4.2 와 맞는 목록(2_4_0)에서 고릅니다. 받은 파일은 models/dxnn/ 에 두고 주소, 크기, sha256 을 out/measure/05_dxnn_sources.md 에 덧붙입니다.

할 일:
1. 단안 깊이: DEEPX 2_4_0 목록에서 깊이 추정 모델(예: FastDepth, SCDepth, MiDaS 계열 등 실제로 목록에 있는 것)을 찾아 받고, probe_dxm1.py 로 입출력을 확인한 뒤 DXM1Backend 에 깊이 출력 경로를 넣습니다. 카메라 2대로 NPU 시간과 FPS 를 잽니다(30초 이내). 깊이 맵을 컬러로 칠한 이미지를 카메라별로 저장하고 눈으로 말이 되는지 봅니다. 지면 평면 거리와의 비교는 보정 후로 남기되, 비교할 코드(검출 박스 아래쪽의 깊이 값과 IPM 거리 비교)는 지금 만들어 둡니다. 상대 깊이라면 지면 점으로 축척을 맞추는 방법을 함께 넣습니다.
2. Hailo 쪽 대안 모델: 파이의 /usr/share/hailo-models 에 있는 HEF 목록을 보고, 세그(예: stdc1, yolov8s_seg, yolov5n_seg 등 실제로 있는 것)와 깊이(scdepthv3 등 있으면) HEF 를 hailortcli run 으로 FPS 를 잽니다. 쓸 만한 것은 HailoBackend 에서 고를 수 있게 하고, 세그를 Hailo 에 두고 검출을 DX-M1 에 두는 반대 배치도 한 번 재서 지금 배치(검출 Hailo, 세그 DX-M1)와 FPS 를 비교합니다.
3. DX-M1 YOLOv8s PPU 의 장치 쪽 점수 문턱값을 확인하고(지난번 확인 필요로 남음), 설정 score_thr 와 어떻게 맞물리는지 정리합니다.
4. 각 모델의 NPU 시간, 전체 FPS, 온도를 표로 남기고, 다음 단계에서 어느 모델을 어느 NPU 에 둘지 추천을 적습니다.

결과는 out/measure/09_npu_models.md 에 씁니다.

공통 규칙:
- DX-M1 에는 아직 방열팬이 없습니다. DX-M1 을 쓰는 실행은 한 번에 30초 이내로 하고, 실행 전후 scripts/dx_temp.py 로 온도를 기록하며, 80도를 넘으면 멈추고 70도대로 식을 때까지 sleep 60 단위(최대 10분)로 기다린 뒤 이어 갑니다.
- Hailo-8 에도 방열판이 없어 연속 실행 720초 만에 120도에 닿아 멈춘 적이 있습니다(out/measure/08_soak_latency.md). Hailo 를 쓰는 실행은 한 번에 60초 이내로 하고, run_demo.py 에는 --health-csv 와 --health-interval 10, --hailo-stop-temp 95 를 붙입니다. 실행 전 Hailo 칩 온도가 85도를 넘으면 sleep 60 단위(최대 10분)로 기다립니다. hailortcli run 벤치도 10초 이내로 합니다.
- 카메라 보정은 아직 안 되어 있습니다(내부 파라미터는 근사값, 위치는 테슬라 모델 Y 배치 가정, configs/two_cam_current.yaml). 거리 값은 의미가 없으니 거리 정확도로 판정하지 마세요.
- 문서 규칙(docs/ 와 out/measure 모두): 첫 문장은 "이 문서는 ~입니다"로 시작합니다. 사람이 쓴 것처럼 자연스러운 존댓말과 쉬운 말을 쓰고, 과장 표현, 이모지와 아이콘, 불릿 남발, 군더더기와 중복, 영어 직역투, 가운뎃점(·), 긴 줄표(—), 문장 안 화살표(→)를 쓰지 않습니다. "활용하다, 수행하다, 다양한, 효과적으로, 원활하게, 를 통해, 를 기반으로"를 쓰지 않습니다. docs/ 문서에는 날짜와 작업 과정 이야기를 넣지 않습니다. 수치에는 조건을 달고 확인 못 한 것은 "확인 필요"라고 적습니다. 표는 3열 이하로 하고 긴 설명은 표 밖 문장으로 씁니다.
- 코드 규칙: 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. 기본 동작을 바꾸는 변경은 옵션으로 넣습니다. 새 코드에는 테스트를 더하고 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.
