빠른 물체 추적과 카메라 끊김 처리를 개선합니다. docs/measurements/11_tracker_latency.md, 14_four_cam.md 를 먼저 읽으세요. 마주 오는 차(상대 25 m/s)를 넣은 시뮬레이션(scripts/make_sim4.py --oncoming, scripts/eval_tracking.py)에서 시각 어긋남이 0이어도 ID 바뀜이 79회로 늘었고 그중 37회가 그 차에서 나왔습니다. 또 실시간 카메라가 한 번 응답하지 못하면 SyncedSources 가 그 카메라를 다시 읽지 않습니다.

할 일:
1. 마주 오는 차에서 ID 가 바뀌는 원인을 숫자로 찾습니다(연결 거리 기준, 속도 추정, 예측 단계의 dt, 측정 잡음 가정, 카메라 경계에서의 투영 점 이동 등). sim 으로 재현하는 테스트를 먼저 만듭니다.
2. 추적기(robust)를 고칩니다. 후보: 칼만 필터 속도 상태와 공분산 기반 게이트(마할라노비스 거리), 상대 속도가 큰 물체를 위한 적응형 게이트, 헝가리안 매칭(scipy 가 없으면 직접 구현), 짧게 사라진 트랙의 예측 유지. 기본 장면과 마주 오는 차 장면, 카메라 2대와 4대에서 지표(ID 바뀜, 물체당 트랙 수, 놓친 프레임 비율, 중복 표시)를 전후로 비교합니다. 기본 장면 지표가 나빠지면 안 됩니다.
3. 카메라 4대 sim 에서 남은 중복 표시(측면 카메라가 차를 옆에서 볼 때 투영점을 차 길이 절반만큼 미는 가정)를 카메라 방향과 물체 방향을 고려하도록 고칩니다.
4. 카메라 끊김: 실시간 카메라가 timeout 을 넘기면 다시 열기를 일정 간격으로 시도하고, 그동안 그 칸은 "신호 없음"으로 표시하며 추적은 나머지 카메라로 계속합니다. 가짜 소스로 끊김과 복구를 테스트하고, 파이에서는 USB 카메라가 없으니 가짜 소스로만 확인합니다.
5. 지표가 확실히 좋아지면 robust 를 기본값으로 바꿀지 판단해 근거를 적되, 기본값 변경은 하지 말고 추천만 합니다.
