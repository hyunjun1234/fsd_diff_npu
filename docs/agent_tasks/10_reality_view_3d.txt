테슬라 리얼리티 뷰처럼 차량 뒤쪽 위에서 내려다보는 3D 화면을 만드는 작업입니다. 지금 데모는 위에서 똑바로 내려다본 탑뷰(BEV)와 카메라 영상만 그립니다. docs/01_fsd_v15_reality_view_research.md 의 리얼리티 뷰 설명, realityview/render.py, pipeline.py, tracker.py 를 먼저 읽으세요.

목표: 파이5 CPU 에서 카메라 2대 데모와 함께 10 FPS 이상 유지되는 3D 시점 렌더러.

할 일:
1. realityview/render3d.py 를 만듭니다. 가상 카메라(자차 뒤쪽 위, 기본 높이와 거리, 내려다보는 각, 화각을 설정으로)를 두고, 지면 격자 또는 지면 영상(IPM 결과를 텍스처로 원근 투영, cv2.warpPerspective 로 가능), 자차 모델(단순 박스나 저폴리 윤곽), 추적된 물체를 클래스별 3D 박스나 단순 모형(사람은 세로 원기둥, 차는 박스)으로 그리고, 도로 마스크가 있으면 지면에 칠합니다. 거리 고리와 물체 ID, 속도 화살표를 선택으로 넣습니다. 외부 의존 없이 numpy 와 OpenCV 만 씁니다(내려받기 금지).
2. 가려짐은 화가 알고리즘(먼 것부터 그리기)으로 처리하고, 물체 박스는 반투명으로 그립니다. 프레임 사이 물체 위치를 부드럽게 보이도록 추적 결과를 보간하는 옵션을 넣습니다.
3. run_demo.py 와 pipeline 에 --view 3d (또는 bev, both) 옵션을 넣고, 기본은 지금 동작(bev)으로 둡니다. 대시보드 배치에서 3D 화면을 크게, 카메라 영상을 작게 두는 배치를 하나 만듭니다.
4. sim 장면(realityview/sim.py)으로 맥에서 결과 이미지를 만들어 눈으로 확인하고(out/measure/10_render3d_sim_*.png), 파이에서 실제 카메라 2대 + Hailo 로 FPS 와 렌더링 시간을 잽니다. 10 FPS 에 못 미치면 저해상도 렌더 후 확대, 지면 텍스처 갱신 주기 줄이기 같은 방법으로 맞춥니다.
5. 사람이 화면을 볼 수 있게 sim 장면 3D 시점 15초 영상(out/video/10_render3d_sim.mp4)과 파이 실제 카메라 15초 영상을 남깁니다. 08 작업에서 --record-video 옵션이 이미 생겼으면 그것을 씁니다.
6. docs/phase1_demo.md 에 3D 시점 사용법을 짧게 더합니다.

결과는 out/measure/10_reality_view_3d.md 에 씁니다.

공통 규칙:
- DX-M1 에는 아직 방열팬이 없습니다. DX-M1 을 쓰는 실행은 한 번에 30초 이내로 하고, 실행 전후 scripts/dx_temp.py 로 온도를 기록하며, 80도를 넘으면 멈추고 70도대로 식을 때까지 sleep 60 단위(최대 10분)로 기다린 뒤 이어 갑니다.
- Hailo-8 에도 방열판이 없어 연속 실행 720초 만에 120도에 닿아 멈춘 적이 있습니다(out/measure/08_soak_latency.md). Hailo 를 쓰는 실행은 한 번에 60초 이내로 하고, run_demo.py 에는 --health-csv 와 --health-interval 10, --hailo-stop-temp 95 를 붙입니다. 실행 전 Hailo 칩 온도가 85도를 넘으면 sleep 60 단위(최대 10분)로 기다립니다. hailortcli run 벤치도 10초 이내로 합니다.
- 카메라 보정은 아직 안 되어 있습니다(내부 파라미터는 근사값, 위치는 테슬라 모델 Y 배치 가정, configs/two_cam_current.yaml). 거리 값은 의미가 없으니 거리 정확도로 판정하지 마세요.
- 문서 규칙(docs/ 와 out/measure 모두): 첫 문장은 "이 문서는 ~입니다"로 시작합니다. 사람이 쓴 것처럼 자연스러운 존댓말과 쉬운 말을 쓰고, 과장 표현, 이모지와 아이콘, 불릿 남발, 군더더기와 중복, 영어 직역투, 가운뎃점(·), 긴 줄표(—), 문장 안 화살표(→)를 쓰지 않습니다. "활용하다, 수행하다, 다양한, 효과적으로, 원활하게, 를 통해, 를 기반으로"를 쓰지 않습니다. docs/ 문서에는 날짜와 작업 과정 이야기를 넣지 않습니다. 수치에는 조건을 달고 확인 못 한 것은 "확인 필요"라고 적습니다. 표는 3열 이하로 하고 긴 설명은 표 밖 문장으로 씁니다.
- 코드 규칙: 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. 기본 동작을 바꾸는 변경은 옵션으로 넣습니다. 새 코드에는 테스트를 더하고 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.
- git commit, push, sudo 금지. 카메라와 NPU 를 쓰는 명령에는 timeout 을 붙입니다. 이미지는 sips -Z 800 으로 줄인 사본을 out/tmp/ 에서 읽습니다. 지울 파일은 out/ 아래에서만 지웁니다. 메모리 파일은 고치지 마세요.
- 마지막 답에는 바뀐 파일, 테스트 결과, 측정 요약 표, 남은 일, 사람이 해야 할 일을 적어 주세요.
