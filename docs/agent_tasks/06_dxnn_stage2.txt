2단계(구현 계획 4.3절)를 실제 .dxnn 모델로 진행하고, 모형 시험용 설정을 만듭니다. 먼저 out/measure/02_dxm1_backend.md, 03_render_mask.md 를 읽으세요.

사람이 정한 것:
- 카메라는 지금 달린 것을 계속 씁니다. 전방 ov5647 은 130도 광각, IR 컷, 야간 가능 제품이라고 합니다(어안에 가까운 렌즈). 후방은 일반 Camera Module 3(imx708).
- 보정과 시험은 실제 차량이 아니라 책상이나 바닥 위 모형으로 먼저 합니다.
- DEEPX 공식 모델 저장소(DEEPX 가 운영하는 공식 사이트, GitHub DEEPX-AI 조직, DEEPX 공식 문서에 적힌 다운로드 주소)에서 미리 컴파일된 .dxnn 을 파이로 내려받아도 됩니다. 다른 출처에서는 받지 마세요. 받은 파일은 파이 저장소 models/dxnn/ 에 두고, 받은 주소와 파일 크기, sha256 을 out/measure/05_dxnn_sources.md 에 기록합니다. dx_engine 3.4.2, DXRT 3.4.2 와 버전이 맞는 모델을 고릅니다.

할 일:
1. 공식 출처에서 YOLOv8s(없으면 YOLOv5s 또는 가장 가까운 YOLO 검출 모델)와 도로를 포함하는 세그 모델(Cityscapes 계열 등) .dxnn 을 찾아 받습니다. 웹 페이지 읽기가 막혀 있으면 파이에서 curl 로 공식 GitHub API(api.github.com/repos/DEEPX-AI/...) 나 공식 문서 주소를 읽어 찾습니다. 찾지 못하면 시도한 주소를 적고 멈춥니다.
2. probe_dxm1.py 로 받은 모델의 입출력 형식을 확인하고 DXM1Backend 의 후처리(검출 출력 형식, PPU 여부, 세그 출력 모양)를 실제 형식에 맞게 마무리합니다. 짐작으로 처리하던 곳의 "확인 필요"를 실측으로 바꿉니다.
3. 카메라 2대로 100프레임을 녹화(out/rec/ 아래 저장, 프레임 파일과 타임스탬프)하는 기능이 없으면 run_demo.py 나 별도 스크립트에 넣고, 같은 녹화를 Hailo YOLOv8s 와 DX-M1 검출로 각각 돌려 FPS, 프레임당 검출 수, 매칭된 박스의 위치 차이(IoU, 중심 거리 px)를 비교한 표를 만듭니다. 방 안에 사람이 없을 수 있으니 검출이 적으면 그렇다고 적고, 대신 out/measure/01_frame_cam*.jpg 같은 정지 영상에서도 비교합니다.
4. 검출은 Hailo, 세그는 DX-M1(3프레임마다) 로 동시에 돌려 FPS 를 재고 1단계 기록(14.2 FPS)과 Hailo 단독(26.2 FPS) 둘 다와 비교합니다. DX-M1 온도는 scripts/dx_temp.py 로 전후 기록하고 85도를 넘으면 식을 때까지 기다립니다.
5. 모형 시험용 설정 configs/two_cam_model.yaml 을 만듭니다. 카메라 높이는 모형 기준(예: 0.15~0.3m, 실측 필요로 표시), BEV 범위와 셀 크기를 모형 크기에 맞게 줄입니다(예: 범위 앞뒤 2m, 셀 0.01~0.02m). 전방 ov5647 은 130도 어안 렌즈로 보고 내부 파라미터 근사값과 왜곡 모델을 어안(OpenCV fisheye)으로 둡니다. camera_model.py 와 IPM 경로가 어안 모델을 지원하지 않으면 지원을 넣고 테스트합니다.
6. scripts/calib_intrinsics.py, calib_extrinsics.py 가 어안 모델과 모형 크기(작은 체커보드, 예: 칸 15~25mm)에서 쓸 수 있는지 확인하고 필요하면 고칩니다. 사람이 모형으로 보정하고 거리 오차를 재는 절차를 docs/phase1_model_rig_calibration.md 에 씁니다. 준비물, 체커보드 인쇄 크기, 카메라별 촬영 명령(복사해서 바로 실행, 결과 저장 위치 한 줄), 보정 명령, 바닥 마커 배치와 외부 보정, 장난감 차나 물체를 놓고 거리 오차를 재는 방법, 모형 기준 완료 기준(내부 RMS 1px 이하, 지면 역투영 오차는 모형 크기에 맞게 비례로 정한 값)을 적습니다. 이 문서는 저장소에 올라갑니다.
7. 테스트를 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.

측정 결과는 out/measure/06_stage2_dxnn.md 에 씁니다.

문서 규칙(docs/ 아래 문서와 out/measure 문서 모두): 첫 문장은 "이 문서는 ~입니다"로 시작합니다. 사람이 쓴 것처럼 자연스러운 존댓말과 쉬운 말을 쓰고, 과장 표현, 이모지와 아이콘, 불릿 남발, 군더더기와 중복, 영어 직역투, 가운뎃점(·), 긴 줄표(—), 문장 안 화살표(→)를 쓰지 않습니다. "활용하다, 수행하다, 다양한, 효과적으로, 원활하게, 를 통해, 를 기반으로" 같은 말을 쓰지 않습니다. docs/ 문서에는 작성일이나 날짜, 작업 과정 이야기를 넣지 않습니다. 수치와 사실에는 출처나 조건을 달고 확인 못 한 것은 "확인 필요"라고 적습니다. 표는 3열 이하로 하고 긴 설명은 표 밖 문장으로 씁니다.

코드 규칙: 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. git commit, push, sudo 금지. 카메라와 NPU 를 쓰는 명령에는 timeout 을 붙입니다. 이미지는 sips -Z 800 으로 줄인 사본을 out/tmp/ 에서 읽습니다. 지울 파일은 out/ 아래에서만 rm 으로 지웁니다.
