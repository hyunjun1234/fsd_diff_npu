4단계(구현 계획 4.6절) 준비 중 모델 파일 없이 할 수 있는 부분입니다. FlashOcc 의 BEVPool(Lift-Splat 의 깊이 분포 x 이미지 특징을 BEV 격자로 모으는 연산)을 CPU 에서 돌리는 구현을 만들고 파이5에서 시간을 잽니다. docs/edge_npu_model_selection.md 의 3장과 5장을 먼저 읽으세요.

제약: 인터넷에서 아무것도 내려받지 마세요(pip install, 가중치, 데이터셋 포함). 지금 설치된 numpy, opencv 와 시스템 컴파일러(gcc/clang, 있으면)만 씁니다. torch 는 쓰지 않습니다.

할 일:
1. realityview/bevpool.py 를 만듭니다. 입력은 카메라별 깊이 확률 (N, D, H, W) 와 특징 (N, C, H, W), 카메라 내부/외부 파라미터, BEV 격자 설정이고 출력은 (C, X, Y) BEV 특징입니다. FlashOcc 와 같은 방식으로, 카메라 설정이 고정이면 frustum 점마다 BEV 셀 인덱스를 미리 계산해 두고(precompute) 매 프레임에는 누적만 합니다.
2. 순수 NumPy 기준 구현(정답용)과 빠른 구현을 둘 다 둡니다. 빠른 구현 후보는 인덱스 정렬 후 np.add.reduceat, np.bincount 채널별, 그리고 시스템 컴파일러가 있으면 ctypes 로 부르는 작은 C 함수(소스는 realityview/_bevpool.c, 빌드는 사용자 권한으로 저장소 안에서, 빌드 산출물은 git 에 올리지 않도록 .gitignore 확인)입니다. 컴파일러가 없거나 빌드가 실패하면 NumPy 경로로 자동으로 돌아갑니다.
3. 테스트: 작은 무작위 입력에서 빠른 구현이 기준 구현과 1e-4 이내로 같은지, 격자 밖 점이 버려지는지, 카메라가 없는 셀이 0 인지 확인합니다. 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.
4. 파이5에서 계획의 4단계 크기로 시간을 잽니다: 카메라 4대, 입력 256x704 에서 특징 1/16 해상도(16x44), D=88(1m~45m 0.5m 간격 근사), C=64, BEV 100x100(0.8m 셀 근사, 필요하면 모델 선정 문서 값을 따름). 카메라 2대 조건도 함께 잽니다. 각 구현의 평균, p95 ms 를 20회 이상 반복으로 기록하고 CPU 스레드 수(1, 4)에 따른 차이도 봅니다.
5. 4단계 목표(카메라 4대 5 FPS, 한 사이클 200ms)에서 BEVPool 이 차지할 몫을 계산해 적습니다.

결과는 out/measure/04_bevpool_cpu.md 에 씁니다. 첫 문장은 "이 문서는 ~입니다"로 시작하고 쉬운 존댓말, 이모지와 가운뎃점(·)과 긴 줄표 없이, 표는 3열 이하, 수치에는 조건을 붙이고 확인 못 한 것은 "확인 필요"로 적습니다.
