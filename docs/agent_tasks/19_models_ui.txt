3D 화면의 물체 모양과 차 안에서 쓰는 조작 화면을 만듭니다. realityview/render3d.py 와 docs/measurements/10_reality_view_3d.md 를 먼저 읽으세요.

제약: 새 패키지와 모델 파일은 내려받지 않습니다. numpy, OpenCV, 파이썬 표준 라이브러리만 씁니다.

할 일:
1. 3D 모양: 지금 박스와 원기둥 대신, 코드로 만든 저폴리 모양(승용차: 차체와 캐빈 두 단, 바퀴 4개 / 트럭과 버스: 긴 상자와 앞 캐빈 / 자전거와 오토바이: 얇은 모양과 바퀴 2개 / 사람: 머리, 몸통, 다리를 단순화한 모양)을 만들고, 면마다 간단한 음영(빛 방향과 법선의 내적)을 넣어 화가 알고리즘으로 그립니다. 물체의 진행 방향(추적 속도)으로 모양을 돌립니다. 자차도 같은 방식의 모양으로 바꿉니다. 옵션(--view3d-models)으로 켜고, 파이 CPU 비용을 재서 물체 20개 기준 3D 화면이 15 FPS 이상인지 확인합니다. 무거우면 단계별 세부 수준(거리별 단순화)을 둡니다.
2. 차 안 조작 화면: 파이에 모니터가 없을 수 있으니, 같은 네트워크의 휴대폰 브라우저로 볼 수 있는 작은 웹 화면을 파이썬 표준 라이브러리(http.server)로 만듭니다. 대시보드 영상을 MJPEG 스트림으로 보여 주고, 버튼으로 화면 종류(bev, 3d, both), 녹화 시작과 멈춤, 트리거 클립 켜고 끄기, 상태 표시(FPS, NPU 와 SoC 온도, 남은 저장 공간, 과열 단계가 있으면 그 단계)를 제공합니다. run_demo.py --web 포트 옵션으로 켜고 기본은 꺼 둡니다. 접속은 같은 네트워크로 제한하고 암호나 토큰 같은 비밀 값은 저장소에 넣지 않습니다(필요하면 실행 때 환경 변수로).
3. 파이에서 --web 을 켜고 맥에서 curl 로 스트림과 버튼 요청이 동작하는지 20초 시험합니다(파이의 주소는 ssh 설정 이름으로만 접속하고 문서에 주소를 적지 않음). 웹 화면을 켰을 때 FPS 하락을 잽니다.
4. sim 장면으로 새 모양의 3D 화면 이미지와 15초 영상(out/video/19_models_sim.mp4)을 만들고 눈으로 확인합니다.
5. docs/phase1_demo.md 에 3D 모양 옵션과 휴대폰 조작 화면 사용법을 더합니다.

결과는 out/measure/19_models_ui.md 에 씁니다.

공통 규칙:
- DX-M1 에는 아직 방열팬이 없습니다. DX-M1 을 쓰는 실행은 한 번에 30초 이내로 하고, 실행 전후 scripts/dx_temp.py 로 온도를 기록하며, 80도를 넘으면 멈추고 70도대로 식을 때까지 sleep 60 단위(최대 10분)로 기다린 뒤 이어 갑니다.
- Hailo-8 에도 방열판이 없어 연속 실행 720초 만에 120도에 닿아 멈춘 적이 있습니다(out/measure/08_soak_latency.md). Hailo 를 쓰는 실행은 한 번에 60초 이내로 하고, run_demo.py 에는 --health-csv 와 --health-interval 10, --hailo-stop-temp 95 를 붙입니다. 실행 전 Hailo 칩 온도가 85도를 넘으면 sleep 60 단위(최대 10분)로 기다립니다. hailortcli run 벤치도 10초 이내로 합니다.
- 카메라 보정은 아직 안 되어 있습니다(내부 파라미터는 근사값, 위치는 테슬라 모델 Y 배치 가정, configs/two_cam_current.yaml). 거리 값은 의미가 없으니 거리 정확도로 판정하지 마세요.
- 문서 규칙(docs/ 와 out/measure 모두): 첫 문장은 "이 문서는 ~입니다"로 시작합니다. 사람이 쓴 것처럼 자연스러운 존댓말과 쉬운 말을 쓰고, 과장 표현, 이모지와 아이콘, 불릿 남발, 군더더기와 중복, 영어 직역투, 가운뎃점(·), 긴 줄표(—), 문장 안 화살표(→)를 쓰지 않습니다. "활용하다, 수행하다, 다양한, 효과적으로, 원활하게, 를 통해, 를 기반으로"를 쓰지 않습니다. docs/ 문서에는 날짜와 작업 과정 이야기를 넣지 않습니다. 수치에는 조건을 달고 확인 못 한 것은 "확인 필요"라고 적습니다. 표는 3열 이하로 하고 긴 설명은 표 밖 문장으로 씁니다.
- 코드 규칙: 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. 기본 동작을 바꾸는 변경은 옵션으로 넣습니다. 새 코드에는 테스트를 더하고 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.
- git commit, push, sudo 금지. 카메라와 NPU 를 쓰는 명령에는 timeout 을 붙입니다. 이미지는 sips -Z 800 으로 줄인 사본을 out/tmp/ 에서 읽습니다. 지울 파일은 out/ 아래에서만 지웁니다. 메모리 파일은 고치지 마세요.
