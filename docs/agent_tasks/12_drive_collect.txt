차량 장착 전에 파이 쪽에서 미리 만들어 둘 수집 도구입니다. docs/07_vehicle_mount_and_training_plan.md 의 7장(데이터 수집), 9.3절(배포와 섀도 실행), 10장, 11장을 먼저 읽고, docs/progress.md 와 scripts/record_frames.py, scripts/run_demo.py, realityview/pipeline.py 를 읽으세요. 지금은 카메라 2대(ov5647, Camera Module 3)지만 나중에 4대가 되므로 카메라 수는 설정에서 읽습니다.

할 일:
1. 주행 녹화 도구: scripts/record_frames.py 를 주행용으로 키우거나 scripts/record_drive.py 를 새로 만듭니다. NPU 추론 없이 카메라 전부의 원본을 받아 세그먼트(예: 60초) 단위로 저장합니다. 저장 형식은 카메라별 H.264 또는 MJPEG 영상과 프레임별 센서 타임스탬프 csv, 회차 메타데이터 json(설정 파일 사본, 카메라 모드, 시작 시각, 파이 상태)입니다. 디스크 남은 공간이 정한 값보다 적으면 녹화를 멈추고, SIGINT 와 SIGTERM 에 세그먼트를 깨끗하게 닫습니다(ACC 꺼짐 안전 종료 대비). 녹화 중 1분마다 프레임 누락 수와 온도를 로그에 남깁니다. 저장된 세그먼트를 --replay 로 바로 넣을 수 있는지 확인합니다(필요하면 ReplaySource 가 영상 파일과 타임스탬프 csv 를 읽게 확장).
2. 녹화 목록과 옮기기: 회차 폴더 구조를 정하고(out/drives/<회차>/<세그먼트>/...), 회차 목록과 용량을 보여 주는 명령과 학습 서버로 옮기는 rsync 명령 예시(대상 주소는 자리표시자)를 문서에 적습니다.
3. 트리거 클립: 실시간 실행(run_demo.py) 중에 링 버퍼로 앞뒤 N초 원본 프레임을 들고 있다가, 검출 점수가 애매한 박스(예: 0.3~0.5)가 나온 프레임, 추적 ID 가 바뀌거나 새로 생긴 순간, 두 NPU 결과가 어긋난 프레임에서 클립을 out/triggers/ 에 저장합니다. 트리거 종류와 점수, 프레임 번호를 json 으로 남기고, 같은 트리거가 너무 자주 나오면 간격을 둡니다. 옵션(--trigger-clips)으로 넣고 기본은 꺼 둡니다.
4. 섀도 실행: 같은 프레임을 Hailo 와 DX-M1 에서 각각 다른 회차 모델로 돌려 결과 차이(박스 매칭 IoU, 놓친 수, 점수 차이)를 프레임마다 csv 로 남기는 모드(--shadow)를 넣습니다. 화면과 추적에는 기본 모델 결과만 씁니다. 회차 모델 선택은 설정의 models 항목(예: det_model_round)으로 하고, 파일 이름 규칙(예: yolov8s_r001.hef, yolov8s_r001.dxnn)을 정합니다. 지금은 회차 모델이 없으니 기존 yolov8s_h8.hef 와 yolov8-s_640x640_ppu.dxnn 을 0회차로 등록합니다.
5. 파이에서 녹화 30초, 트리거 클립과 섀도 실행 각각 20초 이내로 시험합니다(DX-M1 은 30초 이내, 발열 규칙 지킴). 녹화 30초의 파일 크기로 한 시간 녹화에 필요한 저장 공간을 계산합니다.
6. docs/drive_recording.md 를 새로 써서 녹화, 트리거 클립, 섀도 실행, 회차 모델 파일 규칙, 옮기기 명령을 사람이 따라 할 수 있게 정리합니다.

결과는 out/measure/12_drive_collect.md 에 씁니다.

공통 규칙:
- DX-M1 에는 아직 방열팬이 없습니다. DX-M1 을 쓰는 실행은 한 번에 30초 이내로 하고, 실행 전후 scripts/dx_temp.py 로 온도를 기록하며, 80도를 넘으면 멈추고 70도대로 식을 때까지 sleep 60 단위(최대 10분)로 기다린 뒤 이어 갑니다.
- Hailo-8 에도 방열판이 없어 연속 실행 720초 만에 120도에 닿아 멈춘 적이 있습니다(out/measure/08_soak_latency.md). Hailo 를 쓰는 실행은 한 번에 60초 이내로 하고, run_demo.py 에는 --health-csv 와 --health-interval 10, --hailo-stop-temp 95 를 붙입니다. 실행 전 Hailo 칩 온도가 85도를 넘으면 sleep 60 단위(최대 10분)로 기다립니다. hailortcli run 벤치도 10초 이내로 합니다.
- 카메라 보정은 아직 안 되어 있습니다(내부 파라미터는 근사값, 위치는 테슬라 모델 Y 배치 가정, configs/two_cam_current.yaml). 거리 값은 의미가 없으니 거리 정확도로 판정하지 마세요.
- 문서 규칙(docs/ 와 out/measure 모두): 첫 문장은 "이 문서는 ~입니다"로 시작합니다. 사람이 쓴 것처럼 자연스러운 존댓말과 쉬운 말을 쓰고, 과장 표현, 이모지와 아이콘, 불릿 남발, 군더더기와 중복, 영어 직역투, 가운뎃점(·), 긴 줄표(—), 문장 안 화살표(→)를 쓰지 않습니다. "활용하다, 수행하다, 다양한, 효과적으로, 원활하게, 를 통해, 를 기반으로"를 쓰지 않습니다. docs/ 문서에는 날짜와 작업 과정 이야기를 넣지 않습니다. 수치에는 조건을 달고 확인 못 한 것은 "확인 필요"라고 적습니다. 표는 3열 이하로 하고 긴 설명은 표 밖 문장으로 씁니다.
- 코드 규칙: 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. 기본 동작을 바꾸는 변경은 옵션으로 넣습니다. 새 코드에는 테스트를 더하고 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.
