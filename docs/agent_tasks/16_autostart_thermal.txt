차량 시동과 연동할 자동 시작, 안전 종료, 과열 대응을 만듭니다. docs/07_vehicle_mount_and_training_plan.md 의 4장(전원, 시동과 함께 켜고 끄기)과 5.1절(발열), docs/drive_recording.md(있으면)를 먼저 읽으세요.

할 일:
1. 과열 대응(realityview/thermal.py): Hailo 칩 온도, DX-M1 온도(dxrt-cli -s 또는 dx_engine), 파이 SoC 온도, vcgencmd get_throttled 를 주기적으로 읽는 감시 스레드를 만듭니다. 온도 구간별로 단계를 낮춥니다. 예: 정상, 주의(세그와 깊이 주기를 늘림), 경고(DX-M1 작업 멈춤, 검출 프레임 건너뛰기로 FPS 상한 낮춤), 위험(NPU 추론 멈추고 녹화만 유지 또는 깨끗하게 종료). 구간 경계값은 설정으로 두고, 지금까지 실측(Hailo 104도에서 HailoRT 경고, 120도에서 멈춤, DX-M1 85도 이상 위험)을 근거로 기본값을 정해 주석에 적습니다. 단계가 바뀔 때 로그와 화면 표시를 남기고, 온도가 내려가면 히스테리시스를 두고 되돌립니다. run_demo.py 와 녹화 도구에 --thermal 옵션으로 붙입니다.
2. 자동 시작: systemd 사용자 서비스 파일(deploy/systemd/fsd-record.service, fsd-demo.service)을 저장소에 만들고, 부팅 후 자동으로 녹화나 데모를 시작하게 합니다. 설치 명령과, 로그인 없이 사용자 서비스가 돌게 하는 sudo loginctl enable-linger 같은 sudo 명령은 사람이 실행할 명령으로 문서에 적습니다. 서비스 파일 문법은 systemd-analyze verify --user 로 파이에서 확인만 합니다(설치하거나 켜지 마세요).
3. 안전 종료: 전원이 끊기기 전에 신호(예: GPIO 입력, 또는 시험용으로 파일 존재나 SIGTERM)를 받으면 녹화 세그먼트를 닫고 파일을 동기화(os.sync)한 뒤 종료하는 처리를 만듭니다. GPIO 는 gpiozero 나 libgpiod 중 파이에 이미 있는 것을 쓰고(설치 금지), 실제 핀 배선은 07 문서 4장 기준으로 문서에 적되 확인 필요로 둡니다. 실제 poweroff 는 하지 말고 "여기서 sudo poweroff 를 부른다" 자리를 옵션으로 둡니다.
4. 시험: 가짜 온도 값을 넣어 단계 전환과 히스테리시스를 테스트하고, 파이에서 실제 온도로 감시 스레드가 도는지 20초 데모로 확인합니다(Hailo 가 이미 뜨거우니 주의 단계로 들어가는 것을 볼 수 있으면 기록). 안전 종료는 SIGTERM 과 시험용 신호 파일로 녹화 중 종료해 마지막 세그먼트가 깨지지 않는지 확인합니다.
5. docs/vehicle_power_and_autostart.md 를 써서 서비스 설치, 켜고 끄기, 로그 보기, 안전 종료 배선과 시험, 과열 단계와 기준값을 정리합니다.

공통 규칙:
- DX-M1 에는 아직 방열팬이 없습니다. DX-M1 을 쓰는 실행은 한 번에 30초 이내로 하고, 실행 전후 scripts/dx_temp.py 로 온도를 기록하며, 80도를 넘으면 멈추고 70도대로 식을 때까지 sleep 60 단위(최대 10분)로 기다린 뒤 이어 갑니다.
