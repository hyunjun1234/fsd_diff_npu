0단계 장비 상태 점검입니다. 코드는 고치지 말고 점검과 기록만 합니다. 파이 명령은 모두 ssh pi5로 실행합니다.

점검 항목(각 항목마다 실행한 명령과 출력 요약, 통과/실패/확인 필요 판정을 남깁니다):
1. OS: uname -a, /etc/os-release, getconf LONG_BIT(64비트인지), 커널 버전, 파이썬 버전. /boot/firmware/config.txt에 dtparam=pciex1_gen=3 이 있는지(읽기만).
2. PCIe: lspci -nn 으로 ASM2806 스위치, Hailo-8(1e60:2864), DEEPX DX-M1 이 한 부팅에서 모두 보이는지. lspci -vv 에서 각 NPU 링크 속도(LnkSta). dmesg 는 sudo 없이 읽히는 만큼만 hailo, dx, pcie, aer 관련 줄을 봅니다.
3. Hailo 런타임: hailortcli --version, hailortcli fw-control identify(timeout 20초), 파이썬에서 import hailo_platform 가능 여부(시스템 파이썬과 ~/work/fsd_diff_npu/.venv 둘 다). 파이에 있는 HEF 파일 목록(/usr/share/hailo-models, ~/ 아래 *.hef 검색, 깊이 4 정도로 제한)과 각 HEF의 hailortcli parse-hef 요약(입출력 이름과 형식). 특히 yolov8s 계열 HEF가 있는지.
4. DEEPX 런타임: dxcli -s(timeout 20초), dxrt 관련 패키지(dpkg -l | grep -i dx), 커널 모듈(lsmod | grep -i dx), python 에서 import dx_engine 가능 여부(시스템과 .venv 둘 다). *.dxnn 파일 위치.
5. 카메라: rpicam-hello --list-cameras(또는 libcamera-hello) 로 인식된 카메라 수와 센서 이름, 해상도 모드. 실제 촬영은 하지 않습니다.
6. 상태: vcgencmd get_throttled, vcgencmd measure_temp, free -h, df -h /, nproc.
7. 저장소: 맥의 저장소 코드를 규칙에 적힌 rsync 명령으로 파이에 보낸 뒤, 파이 .venv 에서 python3 -m pytest -q 를 돌립니다. 맥에서도 python3 -m pytest -q 를 돌려 비교합니다. 파이 .venv 에 빠진 패키지가 있으면 pip install -r requirements.txt 를 .venv 안에서 해도 됩니다(sudo 없이).
8. 데모 준비도: scripts/run_demo.py --help 와 realityview/detectors.py 의 HailoBackend, realityview/sources.py 의 PiCameraSource 가 파이 환경(picamera2, hailo_platform 버전)과 맞는지 코드를 읽고 맞지 않을 곳을 짚어 둡니다. 고치지는 않습니다.

결과는 파이와 맥 양쪽 out/measure/00_env_check.md 에 정리합니다(파이에서 만들고 rsync 로 받아 오거나 맥에서 직접 작성). 문서 첫 줄은 "이 문서는 ~입니다"로 시작하고, 이모지와 가운뎃점(·)을 쓰지 말고 쉬운 존댓말로 씁니다. 표는 열을 3개 이하로 두고 긴 설명은 표 밖 문장으로 씁니다.

마지막 답에는 위 세 항목(바뀐 파일, 테스트 결과, 남은 일)과 함께, 사람이 sudo 로 해야 할 일(드라이버 설치, config.txt 수정, 재부팅 등)을 복사해 바로 실행할 수 있는 명령으로 따로 정리하고, 1단계 Hailo-8 데모를 바로 돌릴 수 있는지와 막는 것이 무엇인지 한 문단으로 적어 주세요.
