2단계 완료 기준 중 "두 NPU 를 함께 쓸 때의 FPS 가 1단계보다 낮아지지 않는다"를 맞추는 작업입니다. out/measure/02_dxm1_backend.md 를 먼저 읽으세요. 동시 실행에서 14.1 FPS 가 10.9 FPS 로 떨어졌고, 원인은 render.py 의 도로 마스크 덧칠(카메라 2대 39ms)과 BEV 합성의 마스크 처리(+4ms)로 보입니다.

결정 사항: 마스크 덧칠을 OpenCV(cv2.addWeighted, 마스크 영역만 처리, 또는 작은 해상도에서 칠한 뒤 확대 등) 방식으로 바꿔도 됩니다. 화소 값의 반올림 차이(1 이하)는 허용합니다. 기존 테스트가 정확한 화소 값을 비교하면 허용 오차를 두는 쪽으로 고칩니다.

할 일:
1. render.py 와 bev.py 의 마스크 관련 경로를 프로파일링해 시간이 어디서 나가는지 숫자로 확인합니다(맥에서 sim 으로, 이어서 파이에서).
2. 덧칠과 BEV 마스크 처리를 빠르게 고칩니다. 마스크를 매 프레임 새로 칠하지 않고 세그가 갱신될 때만 다시 만드는 캐시도 고려합니다.
3. 파이에서 Hailo 단독과 Hailo + DX-M1 세그 동시(세그 자리에는 지난번처럼 ~/DaeDron 아래 드론 .dxnn 을 읽기만 해서 씀, 마스크는 무작위 50% 로 강제하는 시험 옵션이 있으면 그것도) 를 카메라 2대, 200프레임씩 재고 전후를 비교합니다.
4. DX-M1 이 이전에 89도까지 올랐습니다. DX-M1 을 쓰는 실행은 매번 짧게 하고, 실행 전후 dxrt-cli -s 로 온도를 기록하며, 85도를 넘으면 그 자리에서 멈추고 식을 때까지(70도대) 기다렸다가 진행합니다. 기다림은 sleep 60 단위로 최대 10분입니다.
5. 테스트를 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.

결과는 out/measure/03_render_mask.md 에 씁니다. 첫 문장은 "이 문서는 ~입니다"로 시작하고 쉬운 존댓말, 이모지와 가운뎃점(·)과 긴 줄표 없이, 표는 3열 이하, 수치에는 조건을 붙이고 확인 못 한 것은 "확인 필요"로 적습니다.

규칙: 코드는 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. git commit, push, sudo 금지. 카메라와 NPU 를 쓰는 명령에는 timeout 을 붙입니다. 이미지는 sips -Z 800 으로 줄인 사본을 out/tmp/ 에서 읽습니다.
