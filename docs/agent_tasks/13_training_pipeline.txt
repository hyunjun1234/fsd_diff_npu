차량 장착 전에 학습 서버 쪽에서 미리 만들어 둘 데이터와 학습 파이프라인입니다. docs/07_vehicle_mount_and_training_plan.md 의 6~10장을 먼저 읽으세요. 학습 서버는 사용자의 Windows 데스크탑(RTX 4070 12GB, Ryzen 7950X3D, RAM 64GB)의 WSL2 Ubuntu 22.04 입니다. 이 장비에는 지금 접근할 수 없으니, 코드는 맥에서 작성하고 GPU 없이 도는 부분과 가짜 모델로 테스트하며, GPU 가 필요한 단계는 사용자가 그 데스크탑에서 명령 한 줄로 돌릴 수 있게 만듭니다.

제약: 맥과 파이에서 인터넷으로 아무것도 내려받지 마세요(pip install, 모델 가중치, 데이터셋 포함). 대형 모델(Grounding DINO, SAM 2, Ultralytics, torch)은 import 를 함수 안에서 늦게 하고, 테스트는 가짜 라벨러와 가짜 학습기로 합니다. 파이 쪽 코드는 건드리지 마세요(다른 작업이 realityview/ 와 scripts/run_demo.py, scripts/record_*.py 를 고치는 중입니다). 새 코드는 저장소의 training/ 폴더 아래에만 둡니다.

할 일:
1. training/ 패키지 구조와 데이터 배치 규칙을 정합니다. 회차별 폴더(datasets/r001/...), 원본 주행 녹화(파이의 out/drives/<회차>/<세그먼트> 에 카메라별 영상과 타임스탬프 csv 가 생길 예정)에서 프레임을 뽑아 오는 경로, 고정 시험 세트(학습에 절대 쓰지 않음) 목록 파일, 회차 메타데이터를 정합니다. 설정은 YAML 하나(training/configs/round.yaml 예시)로 받습니다.
2. 프레임 선별(training/select_frames.py): 영상에서 일정 간격으로 뽑고, 흐린 프레임(라플라시안 분산) 제거, 거의 같은 프레임 제거(작은 축소 이미지 해시나 차분), 장면 종류별(밝기로 낮과 밤 추정, 수동 태그 csv) 고르게 뽑기, 트리거 클립(out/triggers/ 의 json) 우선 포함, 고정 시험 세트 고르기와 잠그기(한 번 정하면 이후 회차 선별에서 제외)를 합니다. numpy 와 opencv 만으로 됩니다.
3. 자동 라벨링(training/autolabel.py): 라벨러 인터페이스를 두고 Grounding DINO(박스, 문장 "car . person . truck . bus . bicycle . motorcycle ."), SAM 2(박스 프롬프트로 마스크, 도로는 문장 프롬프트 또는 아래쪽 점 프롬프트), Grounded-SAM-2 영상 추적 구현을 넣습니다. 실제 모델 호출 부분은 공식 저장소의 API 이름을 따르되, 확인 못 한 API 는 주석에 "확인 필요"로 적고 한 함수 안에 모아 고치기 쉽게 합니다. 결과는 YOLO 검출 txt, 세그 마스크 png, 점수 json 으로 저장합니다. 두 라벨러(예: Grounding DINO 와 지금 쓰는 YOLOv8s) 결과가 어긋나는 프레임과 점수가 애매한 박스를 의심 프레임으로 표시합니다.
4. CVAT 연결(training/cvat_io.py): 자동 라벨을 CVAT 에 불러올 형식(YOLO 1.1 또는 CVAT for images 1.1 zip)으로 내보내고, 검수 뒤 CVAT 에서 내보낸 zip 을 다시 읽어 회차 데이터셋에 합칩니다. 검수 대상 목록(의심 프레임 전부와 무작위 표본 비율)을 만듭니다. 사람 라벨과 자동 라벨을 비교해 박스 IoU, 놓친 비율, 잘못 잡은 비율을 내는 training/label_qa.py 를 만듭니다.
5. 학습(training/train_det.py, train_seg.py): Ultralytics 로 직전 회차 best.pt(첫 회차는 yolov8s.pt)에서 시작하고, 이번 회차 데이터에 이전 회차 일부와 COCO 일부를 정한 비율로 섞는 데이터 yaml 을 만듭니다. RTX 4070 12GB 에 맞는 기본 배치 크기와 imgsz 를 정하고 근거를 주석에 적습니다. 세그는 BiSeNetV2 를 도로 1클래스(또는 Cityscapes 라벨 유지)로 미세조정하는 스크립트를 만들되, 쓸 학습 코드(mmsegmentation 등)는 확인 필요로 두고 입력 데이터 준비까지 확실히 합니다.
6. 평가(training/evaluate.py): 고정 시험 세트에서 회차 모델끼리 mAP50, mAP50-95, 클래스별 재현율을 비교하고, 직전 회차보다 예전 장면 성능이 떨어지면 경고합니다. 결과를 docs/measurements/ 에 붙일 수 있는 md 표로 냅니다.
7. 변환(training/export_npu.py): best.pt 에서 ONNX 를 내보내고, Hailo 는 hailomz(재학습한 yolov8s, Hailo-8 용 v2.x 브랜치와 DFC 3.x) 명령과 보정 이미지 폴더 준비, DEEPX 는 DX-COM 설정 json 과 보정 이미지 준비, 또는 Ultralytics export(format="deepx")를 만드는 명령을 만듭니다. 실행 대신 실행할 명령을 출력하는 --dry-run 을 기본으로 둡니다. 결과 파일 이름은 회차 규칙(yolov8s_r001.hef, yolov8s_r001.dxnn)을 따르고, 파이의 models/ 로 보내는 rsync 명령도 출력합니다.
8. 한 회차를 처음부터 끝까지 돌리는 training/run_round.py 와, 각 단계를 가짜 라벨러와 가짜 학습기로 작은 합성 영상에 돌리는 끝에서 끝 테스트를 만듭니다. 테스트는 맥(/usr/bin/python3 -m pytest -q)에서 통과시키고, 파이 테스트는 돌리지 않아도 됩니다.
9. training/requirements.txt(버전 고정, WSL2 Ubuntu 22.04 + CUDA 기준, 확인 못 한 버전은 주석)와 docs/training_pipeline.md(서버에서 설치, 한 회차 돌리는 순서, 각 명령과 결과 위치, CVAT 검수 방법, 변환과 배포, 되돌리기)를 씁니다. Windows 쪽 설치(WSL2, 드라이버)는 다른 문서가 맡으니 "WSL2 Ubuntu 22.04 에 CUDA 가 잡힌 상태"를 출발점으로 둡니다.

결과는 out/measure/13_training_pipeline.md 에 씁니다.

공통 규칙:
- DX-M1 에는 아직 방열팬이 없습니다. DX-M1 을 쓰는 실행은 한 번에 30초 이내로 하고, 실행 전후 scripts/dx_temp.py 로 온도를 기록하며, 80도를 넘으면 멈추고 70도대로 식을 때까지 sleep 60 단위(최대 10분)로 기다린 뒤 이어 갑니다.
- Hailo-8 에도 방열판이 없어 연속 실행 720초 만에 120도에 닿아 멈춘 적이 있습니다(out/measure/08_soak_latency.md). Hailo 를 쓰는 실행은 한 번에 60초 이내로 하고, run_demo.py 에는 --health-csv 와 --health-interval 10, --hailo-stop-temp 95 를 붙입니다. 실행 전 Hailo 칩 온도가 85도를 넘으면 sleep 60 단위(최대 10분)로 기다립니다. hailortcli run 벤치도 10초 이내로 합니다.
- 카메라 보정은 아직 안 되어 있습니다(내부 파라미터는 근사값, 위치는 테슬라 모델 Y 배치 가정, configs/two_cam_current.yaml). 거리 값은 의미가 없으니 거리 정확도로 판정하지 마세요.
- 문서 규칙(docs/ 와 out/measure 모두): 첫 문장은 "이 문서는 ~입니다"로 시작합니다. 사람이 쓴 것처럼 자연스러운 존댓말과 쉬운 말을 쓰고, 과장 표현, 이모지와 아이콘, 불릿 남발, 군더더기와 중복, 영어 직역투, 가운뎃점(·), 긴 줄표(—), 문장 안 화살표(→)를 쓰지 않습니다. "활용하다, 수행하다, 다양한, 효과적으로, 원활하게, 를 통해, 를 기반으로"를 쓰지 않습니다. docs/ 문서에는 날짜와 작업 과정 이야기를 넣지 않습니다. 수치에는 조건을 달고 확인 못 한 것은 "확인 필요"라고 적습니다. 표는 3열 이하로 하고 긴 설명은 표 밖 문장으로 씁니다.
- 코드 규칙: 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. 기본 동작을 바꾸는 변경은 옵션으로 넣습니다. 새 코드에는 테스트를 더하고 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.
