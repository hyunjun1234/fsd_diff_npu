카메라 4대 지원을 지금 장비로 미리 만듭니다. 쿼드 카메라 키트나 새 카메라는 아직 없고, 파이에는 CSI 카메라 2대(ov5647 전방, Camera Module 3 후방)만 있습니다. docs/03_pi5_hailo8_dxm1_implementation_plan.md 2.3절과 4.4절, docs/06_pi5_camera_selection.md, configs/four_cam.yaml, realityview/sources.py 를 먼저 읽으세요.

할 일:
1. USB 카메라 소스: OpenCV VideoCapture(V4L2)로 USB UVC 카메라를 읽는 UsbCameraSource 를 만들고, 카메라마다 CSI 또는 USB 를 설정에서 고를 수 있게 합니다. 하드웨어 동기화가 없으니 프레임마다 받은 시각(time.monotonic_ns 를 센서 시각과 같은 기준으로 맞춤)을 붙입니다. 파이에 USB 카메라가 꽂혀 있는지 확인하고(v4l2-ctl --list-devices, 읽기만), 없으면 가짜 장치로 테스트합니다.
2. 쿼드 키트 소스: 2x2 로 합쳐진 한 프레임을 카메라 4개로 잘라 주는 QuadSplitSource 를 만듭니다(계획 4.4절). 키트의 2번과 3번이 한 프레임 늦다는 점을 설정 값(카메라별 프레임 지연)으로 보정할 수 있게 합니다.
3. 시간 맞춤: 카메라마다 타임스탬프가 다를 때, 기준 카메라 시각에 가장 가까운 프레임끼리 묶는 FrameSyncer 를 만들고(허용 오차 설정, 넘으면 이전 프레임 재사용 또는 빈 칸), 묶음마다 카메라 간 시각 차이를 기록합니다. 추적기에 들어가는 위치를 시각 차이만큼 보정할지는 옵션으로 둡니다.
4. 4대 합성 시뮬레이션: realityview/sim.py 의 4대 장면을 카메라별 영상 파일(out/sim4/cam0..3.mp4 와 타임스탬프 csv, 일부 카메라에 일부러 시각 어긋남과 프레임 누락을 넣음)로 만들고, --replay 로 넣어 4대 BEV 와 3D 화면, 추적이 도는지 확인합니다. tracker robust 기준으로 scripts/eval_tracking.py 지표를 시각 어긋남 0ms, 20ms, 50ms 에서 냅니다.
5. 파이에서 실제 CSI 2대 + 재생 2대(가짜 측면 카메라)를 섞어 4대 구성으로 Hailo 검출 20초를 돌려 FPS 와 단계별 시간을 잽니다(발열 규칙 지킴). 4대 기준 8 FPS 목표(계획 4.4절)와 비교합니다.
6. docs/phase1_demo.md 에 4대 구성 설정 방법(CSI, USB, 쿼드 키트)을 짧게 더합니다.

결과는 out/measure/14_four_cam.md 에 씁니다.

공통 규칙:
- DX-M1 에는 아직 방열팬이 없습니다. DX-M1 을 쓰는 실행은 한 번에 30초 이내로 하고, 실행 전후 scripts/dx_temp.py 로 온도를 기록하며, 80도를 넘으면 멈추고 70도대로 식을 때까지 sleep 60 단위(최대 10분)로 기다린 뒤 이어 갑니다.
- Hailo-8 에도 방열판이 없어 연속 실행 720초 만에 120도에 닿아 멈춘 적이 있습니다(out/measure/08_soak_latency.md). Hailo 를 쓰는 실행은 한 번에 60초 이내로 하고, run_demo.py 에는 --health-csv 와 --health-interval 10, --hailo-stop-temp 95 를 붙입니다. 실행 전 Hailo 칩 온도가 85도를 넘으면 sleep 60 단위(최대 10분)로 기다립니다. hailortcli run 벤치도 10초 이내로 합니다.
- 카메라 보정은 아직 안 되어 있습니다(내부 파라미터는 근사값, 위치는 테슬라 모델 Y 배치 가정, configs/two_cam_current.yaml). 거리 값은 의미가 없으니 거리 정확도로 판정하지 마세요.
- 문서 규칙(docs/ 와 out/measure 모두): 첫 문장은 "이 문서는 ~입니다"로 시작합니다. 사람이 쓴 것처럼 자연스러운 존댓말과 쉬운 말을 쓰고, 과장 표현, 이모지와 아이콘, 불릿 남발, 군더더기와 중복, 영어 직역투, 가운뎃점(·), 긴 줄표(—), 문장 안 화살표(→)를 쓰지 않습니다. "활용하다, 수행하다, 다양한, 효과적으로, 원활하게, 를 통해, 를 기반으로"를 쓰지 않습니다. docs/ 문서에는 날짜와 작업 과정 이야기를 넣지 않습니다. 수치에는 조건을 달고 확인 못 한 것은 "확인 필요"라고 적습니다. 표는 3열 이하로 하고 긴 설명은 표 밖 문장으로 씁니다.
- 코드 규칙: 파일 맨 위 설명 블록 없이 바로 시작하고 역할별로 구획을 나누며 쉽고 꼼꼼한 주석을 답니다. 기본 동작을 바꾸는 변경은 옵션으로 넣습니다. 새 코드에는 테스트를 더하고 맥(/usr/bin/python3 -m pytest -q)과 파이(.venv)에서 통과시킵니다.
